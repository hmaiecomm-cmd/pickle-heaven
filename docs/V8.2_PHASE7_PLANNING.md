### 功能组 B：异常规则引擎（优先级：P1）

#### B1. 自定义告警规则

**目标**：让管理员定义异常自动升级和通知规则

**功能设计**：
```
规则编辑器
├─ 条件定义
│  ├─ 异常类型 = [选择]
│  ├─ 严重程度 >= [选择]
│  ├─ 持续时间 > [输入] 分钟
│  └─ 频率 > [输入] 次/小时
│
├─ 动作定义
│  ├─ 自动升级为严重异常
│  ├─ 发送通知
│  │  ├─ LINE 通知
│  │  ├─ 邮件通知
│  │  └─ 短信通知
│  └─ 自动隔离设备
│
└─ 规则模板
   ├─ 高频异常规则
   ├─ 关键设备异常规则
   └─ 工作时间异常规则
```

**数据库设计**：
```prisma
model AnomalyRule {
  id String @id @default(cuid())
  name String
  description String?
  
  // 条件
  anomalyTypes String[] // JSON 数组
  minSeverity String
  durationMinutes Int?
  frequencyPerHour Int?
  
  // 动作
  autoEscalate Boolean @default(false)
  notificationChannels String[] // ['LINE', 'EMAIL', 'SMS']
  autoIsolate Boolean @default(false)
  
  // 元数据
  enabled Boolean @default(true)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  
  venue Venue @relation(fields: [venueId], references: [id])
  venueId String
}
```

**工作量估计**：5-7 天

  3️⃣ 更新固件（成功率：60%）

用户可一键执行，系统自动验证效果

### 功能组 D：预测分析（优先级：P2）

#### D1. 异常趋势预测

**目标**：使用简单的 ML 预测未来异常趋势

**方案**：
- 时间序列分析（ARIMA 或简单移动平均）
- 周期性检测（周末 vs 工作日）
- 异常尖峰预警

**示例预测**：
```
预测（未来 7 天）：
  Mon: 预计 5-8 个异常（概率：75%）
  Tue: 预计 6-10 个异常（概率：82%）
  ...

告警：周二预计异常数 ↑ 40%（可能原因：周期性高峰）
```

**工作量估计**：5-7 天

---

#### D2. 根本原因分析（RCA）

**目标**：自动分析异常的根本原因

**功能**：
- 相关异常聚类
- 时序关联分析
- 因果链路识别

**示例**：
```
故障链：
  1️⃣ 控制器网络连接丢失
     ↓
  2️⃣ 命令执行失败
     ↓
  3️⃣ 设备状态不同步
     ↓
  4️⃣ 状态不符告警
```

**工作量估计**：6-8 天

## 风险评估

### 高风险项

**D1. 异常趋势预测**
- 风险：数据不足、模型过拟合
- 缓解：从简单移动平均开始，逐步引入 ML

**D2. 根本原因分析**
- 风险：复杂度高、准确度难以保证
- 缓解：先实现相关异常聚类，后续迭代改进

### 中等风险项

**B1. 自定义规则**
- 风险：规则冲突、执行出错
- 缓解：严格的规则验证、沙箱执行环境

**C2. 一键恢复**
- 风险：误操作导致故障扩大
- 缓解：所有恢复需审批、执行回滚机制
