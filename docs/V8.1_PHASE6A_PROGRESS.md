## Phase 6a 完成內容

### 1. Prisma Schema 更新

**檔案**：`prisma/schema.prisma`

新增 Model：`DeviceAnomaly`

```prisma
model DeviceAnomaly {
  id String @id @default(cuid())
  
  // 關聯
  circuitId String
  circuit Circuit @relation(fields: [circuitId], references: [id], onDelete: Cascade)
  
  // 異常信息
  type String              // 異常類型 (7 種)
  severity String          // 嚴重程度 (warning/error/critical)
  status String @default("pending")  // 狀態 (pending/acknowledged/resolved)
  
  // 時間戳
  occurredAt DateTime @default(now())
  lastReportedAt DateTime @updatedAt
  
  // 操作信息
  acknowledgedBy String?
  acknowledgedAt DateTime?
  resolvedBy String?
  resolvedAt DateTime?
  
  // 備註
  notes String?
  
  // 審計
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  
  // 索引優化
  @@index([circuitId])
  @@index([status])
  @@index([severity])
  @@index([occurredAt])
}
```

### 3. API 端點實現

#### 3.1 GET 異常列表

**端點**：`GET /api/admin/devices/[circuit]/anomalies`

**檔案**：`src/app/api/admin/devices/[circuit]/anomalies/route.ts`

功能：
- 查詢特定迴路的異常列表
- 支持按狀態、嚴重程度篩選
- 支持分頁（limit / offset）
- 計算迴路的健康狀態
- 返回異常計數和詳細信息

**查詢參數**：
- `status`：pending | acknowledged | resolved
- `severity`：warning | error | critical
- `limit`：分頁大小（預設 50，最大 500）
- `offset`：分頁偏移（預設 0）

**響應示例**：
```json
{
  "success": true,
  "data": {
    "circuit": "12",
    "health": "critical",
    "anomalyCount": 2,
    "anomalies": [
      {
        "id": "anom_xxx",
        "type": "controller_offline",
        "severity": "critical",
        "status": "pending",
        "occurredAt": "2026-11-16T10:00:00Z",
        "lastReportedAt": "2026-11-16T10:05:00Z",
        "notes": null
      }
    ],
    "pagination": {
      "limit": 50,
      "offset": 0,
      "total": 2
    },
    "lastUpdated": "2026-11-16T10:05:00Z"
  }
}
```

#### 3.2 POST 確認異常

**端點**：`POST /api/admin/devices/[circuit]/anomalies/[id]/acknowledge`

**檔案**：`src/app/api/admin/devices/[circuit]/anomalies/[id]/acknowledge/route.ts`

功能：
- 確認異常（狀態從 pending → acknowledged）
- 記錄確認人和確認時間
- 支持添加操作備註
- 防止重複確認

**請求體**：
```json
{
  "acknowledgedBy": "admin@example.com",
  "notes": "已確認，正在處理"
}
```

**響應示例**：
```json
{
  "success": true,
  "data": {
    "id": "anom_xxx",
    "status": "acknowledged",
    "acknowledgedBy": "admin@example.com",
    "acknowledgedAt": "2026-11-16T10:06:00Z",
    "notes": "已確認，正在處理"
  }
}
```

#### 3.3 POST 解決異常

**端點**：`POST /api/admin/devices/[circuit]/anomalies/[id]/resolve`

**檔案**：`src/app/api/admin/devices/[circuit]/anomalies/[id]/resolve/route.ts`

功能：
- 解決異常（狀態從 pending/acknowledged → resolved）
- 記錄解決人和解決時間
- 支持添加解決備註
- 防止重複解決

**請求體**：
```json
{
  "resolvedBy": "admin@example.com",
  "notes": "已修復，恢復正常運作"
}
```

## 技術實現細節

### 數據庫查詢

異常列表查詢使用多個索引優化：
- `circuitId`：快速定位迴路
- `status`：快速篩選狀態
- `severity`：快速篩選嚴重程度
- `occurredAt`：快速排序按時間

### 健康狀態計算

使用 Phase 5 定義的 `determineHealth()` 函數：
- 根據異常列表計算迴路的整體健康狀態
- 優先級：critical > error > warning > (healthy)

### 錯誤處理

API 實現了完整的錯誤處理：
- 400：無效的請求（迴路格式、缺少字段）
- 404：異常或迴路不存在
- 500：伺服器錯誤

### 驗證層

- 迴路編號驗證：必須是 2 位數字 (^\d{2}$)
- 狀態衝突檢查：防止重複操作
- 數據庫約束：cascade delete 確保數據一致性

## 測試命令

### 本機測試 API

```bash
# 啟動開發服務器
npm run dev

# 測試獲取異常列表
curl "http://localhost:3000/api/admin/devices/12/anomalies"

# 測試確認異常（需要有異常記錄）
curl -X POST "http://localhost:3000/api/admin/devices/12/anomalies/[anomaly-id]/acknowledge" \
  -H "Content-Type: application/json" \
  -d '{"acknowledgedBy":"admin@example.com"}'

# 測試解決異常
curl -X POST "http://localhost:3000/api/admin/devices/12/anomalies/[anomaly-id]/resolve" \
  -H "Content-Type: application/json" \
  -d '{"resolvedBy":"admin@example.com"}'
```
