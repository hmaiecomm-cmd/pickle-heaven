## 數據模型設計

### DeviceAnomaly Model

```prisma
model DeviceAnomaly {
  id String @id @default(cuid())
  
  /// 關聯迴路
  circuitId String
  circuit Circuit @relation(fields: [circuitId], references: [id], onDelete: Cascade)
  
  /// 異常類型
  type String // 'disconnected' | 'malfunction' | 'controller_offline' | etc.
  
  /// 嚴重程度
  severity String // 'warning' | 'error' | 'critical'
  
  /// 異常狀態
  status String // 'pending' | 'acknowledged' | 'resolved'
  
  /// 時間戳
  occurredAt DateTime @default(now())
  lastReportedAt DateTime @updatedAt
  
  /// 確認信息
  acknowledgedBy String?
  acknowledgedAt DateTime?
  
  /// 解決信息
  resolvedBy String?
  resolvedAt DateTime?
  
  /// 備註
  notes String?
  
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  
  @@index([circuitId])
  @@index([status])
  @@index([severity])
  @@index([occurredAt])
}
```

## API 規格設計

### 1. GET 異常列表

**端點**：`GET /api/admin/devices/[circuit]/anomalies`

**查詢參數**：
- `status` (可選)：pending | acknowledged | resolved
- `severity` (可選)：warning | error | critical
- `limit` (可選，預設 50)：分頁大小
- `offset` (可選，預設 0)：分頁偏移

**響應**：
```json
{
  "success": true,
  "data": {
    "circuitId": "01",
    "health": "critical",
    "anomalyCount": 2,
    "anomalies": [
      {
        "id": "anom_xxx",
        "type": "controller_offline",
        "severity": "critical",
        "status": "pending",
        "occurredAt": "2026-11-16T10:00:00Z",
        "lastReportedAt": "2026-11-16T10:05:00Z",
        "notes": null
      },
      {
        "id": "anom_yyy",
        "type": "command_failed",
        "severity": "critical",
        "status": "pending",
        "occurredAt": "2026-11-16T09:55:00Z",
        "lastReportedAt": "2026-11-16T10:04:00Z",
        "notes": null
      }
    ],
    "lastUpdated": "2026-11-16T10:05:00Z"
  }

```

**錯誤**：
- 404：迴路不存在

- 500：伺服器錯誤

## 前端 Hook 設計

### useDeviceAnomalies Hook

```typescript
function useDeviceAnomalies(circuitId: string) {
  const [anomalies, setAnomalies] = useState<DeviceAnomaly[]>([])
  const [health, setHealth] = useState<DeviceHealth>('healthy')
  const [isLoading, setIsLoading] = useState(true)
  const [error, setError] = useState<Error | null>(null)

  useEffect(() => {
    const fetchAnomalies = async () => {
      try {
        setIsLoading(true)
        const res = await fetch(`/api/admin/devices/${circuitId}/anomalies`)
        if (!res.ok) throw new Error('Failed to fetch anomalies')
        const data = await res.json()
        setAnomalies(data.data.anomalies)
        setHealth(data.data.health)
      } catch (err) {
        setError(err as Error)
      } finally {
        setIsLoading(false)
      }
    }

    fetchAnomalies()
    const interval = setInterval(fetchAnomalies, 10000) // 10 秒輪詢
    return () => clearInterval(interval)
  }, [circuitId])

  return { anomalies, health, isLoading, error }
}
```

### useAnomalyWebSocket Hook

```typescript
function useAnomalyWebSocket(enabled = true) {
  const [isConnected, setIsConnected] = useState(false)
  
  useEffect(() => {
    if (!enabled) return

    const protocol = window.location.protocol === 'https:' ? 'wss:' : 'ws:'
    const ws = new WebSocket(`${protocol}//${window.location.host}/api/ws/anomalies`)

    ws.onopen = () => setIsConnected(true)
    ws.onclose = () => setIsConnected(false)
    ws.onmessage = (event) => {
      const data = JSON.parse(event.data)
      // 廣播異常事件
      window.dispatchEvent(new CustomEvent('anomaly-update', { detail: data }))
    }

    return () => ws.close()
  }, [enabled])

  return { isConnected }
}
```

## 技術決策

### API 設計選擇

| 決策 | 選項 | 原因 |
|---|---|---|
| 實時推送 | WebSocket vs REST 輪詢 | WebSocket 優先，輪詢作為備用（iPhone Safari 支持限制） |
| 數據查詢 | 過濾 vs 分頁 | 支持兩者，預設分頁防止大型響應 |
| 錯誤處理 | HTTP 狀態碼 vs JSON 錯誤 | 兩者結合：狀態碼 + JSON 詳細信息 |

### 數據驗證

- 前端：React Hook Form 驗證
- 後端：Zod 或 Prisma 驗證
- 權限：middleware 驗證 admin 權限

## 已知注意事項

1. **Turso SQLite 限制**
   - 無實時變更通知，使用輪詢或 webhook
   - 事務支持受限，需要特殊處理

2. **WebSocket 支持**
   - 需要檢查 Vercel 無伺服器環境是否支持
   - 可能需要使用消息隊列（如 Bull）替代

3. **性能考慮**
   - 異常查詢可能返回大量數據，需要分頁
   - 首頁載入時間需要監控

4. **權限設計**
   - 不同角色可能有不同的異常可見性
   - 確認/解決操作需要記錄操作人
